## 5. How to use each artefact

### Contract freeze (`tests/fixtures/contract/`)

Machine-generated. Never hand-edit the JSON/SQL.

```
.venv/Scripts/python.exe tests/fixtures/contract/generate.py
.venv/Scripts/python.exe tests/fixtures/contract/generate.py --check
.venv/Scripts/python.exe tests/fixtures/contract/generate.py --build-db PATH
```

`generate.py` sets `AGMT_DB` to a temp path *before* any `agent.*` /
`server.app` import. The live `data/agmt.db` is not the Store target.

Hazards already handled in the generator (do not “improve” past them):

- **H1** `run_checks` only prints an exit code. Mechanical findings come
  from `load_corpus` → `build_document` → `mechanical_checks` →
  `normalize_issue`.
- **H2** `POST /api/settings` with a populated body writes `config.yaml`
  (live API key). The generator posts exactly `{}`.
- **H3** `GET /api/models` hits OpenRouter unless `router.catalog` is
  stubbed. The generator stubs it and replaces `_client` with a
  no-network object.
- **H4** `has_key` / `pinned` are forced to `false` / `{}` because
  `config.yaml` is gitignored.
- **H5** Store is a process singleton. Env must be set before import.

`v1_store_schema.sql` is `sqlite_master` DDL (no `IF NOT EXISTS`).
`legacy_v1.sql` is `iterdump()` after Store public methods: two
`save_run`s, every `VALID` disposition, one promoted active position.

### Contextual fixtures (`tests/fixtures/contextual/`)

Design contract for plan commit 18. Schemas in plan 5.2 / 5.3 do not
exist in code yet.

```
.venv/Scripts/python.exe tests/fixtures/contextual/validate.py
.venv/Scripts/python.exe tests/fixtures/contextual/validate.py --list
```

Load-bearing rule: the resolver may choose among deterministically
produced candidate IDs and must never invent an unresolved clause.
Cases that fail a guessing resolver:
`ambiguous_two_indemnity_clauses`,
`relative_clause_above_table_ambiguous`,
`definition_losses_not_found`,
`indemnity_only_in_defined_term`.

Worked example from plan 10.3: `check_indemnity_double_recovery`.

Document version hashes in these fixtures are synthetic labels
(`sha256:doc-v1-aurora-sha-current` vs
`sha256:doc-v2-aurora-sha-after-edit`), not real hex.
`selected_text_sha256` / `old_text_sha256` are real SHA-256.

### Word matrix (artefact 4)

A host that cannot provide a capability must report `false` plus a
reason. Absence is not a clean bill of health.
`taskpane.js` 429–431 currently prints “No mechanical defects found”
when `findings` is empty — that is the failure mode the matrix warns
about. Word Online undo, and native Ctrl+Z of Office.js writes on
desktop, are `unverified`.

### Companion protocol (artefact 6)

Intended future behaviour. Nothing in the tree implements it.
Transport: loopback WebSocket, companion is the server, add-in is the
client, `ws://127.0.0.1:17321/v1`.
Frozen pairing rule: `pairing_token == pairing_code` (6-digit). Tests
set `AGMT_PAIRING_TOKEN`.
Fake companion stdin: `press` → `partial*` → `release` → `final`.
`final` is only accepted from state `release_received`.
Three MUST NOTs: no document text on the bridge, no Word write
authority, no Word COM.

### Release checklist (artefact 7)

`agent.eval checks` owns the 29/29 must-finds / 0-trap gate.
`agent.eval run` owns `anchor_pass_rate` and `overlap_compliance` 1.00.
Attaching the 1.00 gates to `checks` is a fabricated pass condition.

CI (`.github/workflows/eval-checks.yml`) currently runs only `checks`
plus `tests/test_pipeline.py`. `agent.eval run` always exits 0,
including after a printed load/parse exception. The 1.00 gate must
read `reports/eval-run.json` until the CLI grows a threshold flag.

## 6. Known landmines in the current code

1. `Supervisor.run` calls `get_store().save_run()`
   (`agent/supervisor.py` ~289). `tests/test_pipeline.py` supervisor
   tests do **not** set `AGMT_DB`, so they write the live
   `data/agmt.db`. Size/hash of that file will change after a local
   test run. That is pre-existing, not a fixture bug.
2. `server/app.py` builds `cfg` and `Router(cfg)` at import time.
   Import order matters for any new test that touches settings.
3. `GET /api/models` is a live network call. Offline it returns a
   socket-repr error string. Never snapshot it unstubbed.
4. Do not post a populated `/api/settings` body in tests. It can
   overwrite the user’s OpenRouter key in `config.yaml`.
