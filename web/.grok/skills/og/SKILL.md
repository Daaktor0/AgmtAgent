# Open Graph and brand assets

Use when changing brand assets, site identity or social metadata, or preparing a release that requires the brand gate.

## Brand-asset pass:

The app must have an explicit identity in src/lib/og/site.json. Games and visually rich apps also need a 1200x630 public/og.jpg, "card": "custom", "type": "x:game", and a 1200x264 public/x-banner.jpg. Plain utilities may keep the platform placeholder.

Use the checked-in brand gate before reporting the pass:

~~~
node scripts/brand-check.mjs --placeholder-ok
~~~

A background asset generation marker is /workspace/.grok/og-pending; it is only valid for 10 minutes. Do not block unrelated work on optional background assets. When assets are required deliverables, await the generation result using the available runtime tools, then run the brand gate against the completed files. A pending marker is not evidence that the assets are complete.

Stage generated bytes under .grok/, validate them, and hand them over atomically. Never stage a temporary file inside public/:

~~~
node scripts/write-atomic.mjs .grok/og.jpg.tmp public/og.jpg
node scripts/write-atomic.mjs .grok/x-banner.jpg.tmp public/x-banner.jpg
node scripts/write-atomic.mjs .grok/site.json.tmp src/lib/og/site.json
~~~

Do not publish a placeholder as a custom card, fabricate an image, or claim the required brand pass complete while the filesystem gate is failing.
